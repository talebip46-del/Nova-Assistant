# 🚀 Nova Assistant

> **دستیار هوش مصنوعی محلی شما — با ماژول کدنویسی Nova Code — برای ساخت پروژه‌های واقعی از صفر تا صد: وب‌سایت، ابزار، بازی و اسکریپت**

> 🤖 **مخصوص اتصال با Ollama:** این پروژه برای اتصال به Ollama و استفاده از مدل‌های لوکال طراحی شده است.
>
> ⚠️ **پیشنهاد می‌کنم API key بهش وصل نکنید** — بخش ارائه‌دهنده‌های ابری هنوز **نیمه‌کاره** است؛ تا تکمیل نشده فقط از مدل‌های لوکال استفاده کنید.

**Nova Assistant** برنامه‌ی اصلی است و **Nova Code** ماژول/بخش کدنویسیِ درون آن. Nova Assistant فقط چت‌بات نیست؛ یک **ایجنت** است که کد را واقعاً می‌سازد:

- 📁 کد را **داخل فایل‌های واقعی** در پوشه Workspace می‌نویسد — قفل‌شده روی همان پوشه
- 🌐 برای **وب‌سایت‌ها**: فایل‌های `index.html` + `css/style.css` + `js/main.js` می‌سازد و با `/serve` پیش‌نمایش زنده می‌دهید
- 🐛 وقتی برنامه خطا بدهد، خطا را می‌خواند، فایل‌های مرتبط را خودش پیوست می‌کند، ریشه‌یابی می‌کند و کد را کامل اصلاح می‌کند
- 🔍 **یادگیری از وب**: با `/learn` و `/search` اطلاعات خود را از منابع معتبر (MDN، مستندات رسمی، Stack Overflow، Wikipedia) به‌روز می‌کند؛ حتی خود مدل وسط جواب می‌تواند درخواست جستجو بدهد
- 🧠 **مغز قوی‌تر (v2.5)**: پرامپت مدل بازنویسی شده — پروتکل فایل با مثال عملی، قوانین زبانی (Python / JavaScript / HTML+CSS / SQL)، مدیریت هوشمند پنجره متن و پاسخ‌هایی که هرگز در کلاهک توکن محبوس نمی‌شوند
- 🐢 مخصوص لپ‌تاپ ضعیف: هیچ پاسخی وسط کار قطع نمی‌شود؛ تایمر «waiting» نشان می‌دهد مدل زنده است و مدل هم در رم می‌ماند تا بعد از هر مکث دوباره بارگذاری نشود
- ✅ `/check` سینتکس همه فایل‌های `.py` و `.js` را قبل از اجرا بررسی می‌کند
- 💾 بکاپ خودکار قبل از هر تغییر + `/undo` که کل آخرین دسته تغییرات را برمی‌گرداند
- 🇬🇧 تمام ترمینال انگلیسی؛ گفتگو با مدل فارسی هم می‌تواند باشد (کد همیشه انگلیسی)
- 🔒 هسته صددرصد آفلاین و محلی؛ جستجوی وب **اختیاری** است — بدون اینترنت هم همه‌چیز کار می‌کند

**یک برنامه، دو چهره:** ایجنت ترمینال (`app/nova` یا `app/novacode`) و وب (`app/nova --web`) **همان یک ایجنت‌اند** — فقط با یک گزینه فرق می‌کنند. هر دو فایل می‌سازند، ابزار دارند، و مغزشان قابل تعویض است — به **دو روش لوکال**: ۱) هر مدلی که داخل **Ollama** نصب کرده باشید (خودکار شناسایی می‌شوند)، ۲) هر فایل مدلی (**GGUF**) که دانلود کرده و در **پوشه مدل‌ها** ریخته باشید — یا هر API ابری با `/provider` (openai، openrouter، groq، deepseek، anthropic، gemini، custom).

## 🎨 نسخه ۸.۹.۰ «design layers» — لایه‌های اختیاری طراحی: انتخاب با هوش مصنوعی، نه قانون

> «بیا nova design رو پیشرفته کنیم و برای دیزاین چند لایه‌ی اختیاری اضافه کنیم که هوش مصنوعی خودش انتخاب کنه اینها رو اضافه کنه یا خیر و یا اصلاً چه جاهایی اضافه کند … نباید خلاقیت رو از هوش مصنوعی گرفت و اینها گزینه هستند و قانون نیستند»

- **پروتکل اعلام — یک متا یا فقط کلاس**: مدل با `<meta name="nova-layers" content="shadow=1..5; glass=1..4; motion=float,fade-down,fade-up,slide-in,pop,glow|all">` هر لایه را (با سطحِ حال‌وهوایش) اعلام می‌کند — یا حتی بدون متا فقط از کلاس‌ها استفاده می‌کند؛ هر دو درخواست است. گرامر تحمل‌پذیر: واژه یا رقم (ارقام فارسی هم)، جداکننده‌ی آزاد، ناشناخته‌ها نادیده، `off` = نمی‌خواهم. دستِ مدل برای «کجا» کاملاً باز است: نوا فقط تحویل می‌دهد.
- **سه لایه‌ی آماده**: ① **مقیاس سایه ۵ سطح** (ظریف → دراماتیک) با `.nv-shadow-1..5` + `.nv-hover-lift`؛ سطح اعلام‌شده توکن‌های کف طراحی را سراسری بازتنظیم می‌کند (حال‌وهوا کل سایت را می‌گیرد) ② **شیشه‌ی مات ۴ سطح** (تیز → خیلی نرم، `.nv-glass-1..4`) مستقل از رنگ و فونت (تینت جدا با `--nv-glass-tint` برای سایت تاریک؛ `@supports` برای مرورگرهای بدون backdrop-filter) ③ **شش حرکت ظریف** (`float` شناور آرام، `fade-down` محو از بالا، `fade-up`، `slide-in`، `pop`، `glow`) + `.nv-stagger` برای آبشار — همه داخل گارد `prefers-reduced-motion`، ورودی‌ها یک‌بار، لوپ‌ها آرام.
- **تحویل قطعیِ بی‌دست‌درباف**: بعد از هر اعمال، `design_polish` اجتماعِ درخواست‌ها را در **یک** `nova-layers.css` قطعی می‌نویسد و لینک را قبل از `</head>` (بعد از کف و استایل‌های خود صفحه — آبشار درست) تزریق می‌کند؛ شیت با دورهای بعدی **merge** می‌شود (اتحاد هرگز کوچک نمی‌شود)، فایلِ خودکاربر هرگز بازنویسی نمی‌شود، دورِ بدون‌تغییر کاملاً بی‌صدا، fail-soft در همه‌سطح، آفلاین و صفر call مدل.
- **خلاقیت محفوظ**: بند تازه‌ی قرارداد طراحی صریح می‌گوید «options, never rules - skip freely … a calm design may omit the tag entirely» — کف زیبایی و پالت‌های v7.2 دست‌نخورده (`floor_css(None)` بایت‌یکسان).

## 🚦 نسخه ۸.۸.۰ «pre-run gate» — اول مطمئن شو، بعد اجرا کن

> «بعد اینکه کد آماده شد و دکمه‌ی run رو می‌زنم یهویی خطای سینتکسی پیدا میشه و میره درست کردنش — من می‌خوام قبل از اجرا مطمئن شن؛ و وقتی میره درست کنه انگار توی لوپ گیر می‌کنه و تموم نمیشه»

- **ترمز لوپ اصلاح**: گارد «خطای تکراری» در /auto و /verify که بایت‌به‌بایت مقایسه می‌کرد و یک شماره‌ی خطِ جابه‌جا گارد را دور می‌زد — حالا امضای نرمال‌شده (`error_signature`) هم سنجیده می‌شود؛ به‌علاوه بودجه‌ی سطح-جلسه‌ی `MAX_FIX_ROUNDS=3` (`NOVA_FIX_ROUNDS`): بعد از دورهای پیاپیِ بدون اجرای سبز، autofix با پیام صادقانه می‌ایستد و فقط با اجرای سبز یا `/autofix on` دوباره مسلح می‌شود.
- **وب**: کارت «خطای سینتکس پیش از اجرا — دستور اجرا نشد» (`prerun_reject`) + بازمسلح‌سازی بودجه با `/autofix on`.

## 🛡️ نسخه ۸.۷.۰ «stability sweep» — دورِ کاملِ پایدارسازی: تک‌تک فایل‌ها، تک‌تک کدها

## 🏹 نسخه ۸.۵.۰ «bug hunter» — باگ‌هایی که سینتکس نمی‌بیند: دکمه‌ی مرده، فایل گم‌شده، کرشِ اجرا، نیازِ جاافتاده

> «نوا یک مشکل بزرگ داره — ممکنه کدهایی بسازه که از نظر سینتکس مشکلی ندارن ولی باگ داشته باشن؛ مثلاً یک بخش از کار بیفته یا اصلاً یک دکمه یا هر چیز دیگه‌ای کار نکنه. یک راه حل پیدا کن که نوا بتونه تمام مشکلات و باگ‌ها رو بگیره»

- **تشخیص**: نگهبان v8.4 سینتکس را گرفتن گرفته بود؛ ولی چهار خانواده‌ی باگ از دروازه‌اش سالم رد می‌شدند: ① دکمه‌ی مرده (JS المان/تابعی را صدا می‌زند که هیچ‌جا وجود ندارد) ② فایلِ هرگز-نوشته‌شده (`<script src="app.js">` به فایلی که تولید نشده) ③ کرش در اولین اجرا (`NameError`، `ReferenceError`...) ④ نیازِ جاافتاده (کاربر «با لاگین و خروج» خواسته، لاگین تحویل نشده). پاسخ: ماژول جدید **`nova_probe.py`** با چهار پراب رفتاری.
- **پراب سیم‌کشی (قطعی، آفلاین، صفر مدل)**: گراف المان‌ها روی کل بسته + پروژه ساخته می‌شود — تعریف‌ها (id در html و template literal ها و `el.id=`، کلاس‌ها، ۶ الگوی تعریف تابع JS) در برابر ارجاع‌ها (`getElementById`، `querySelector` با سلکتور مرکب، `classList`، هندلرهای inline، `src/href` محلی، `from .mod import` پایتون با ast، `require("./x")` نود با نرمال‌سازی `../`). ارجاع مرده = **رد اتمیک بسته قبل از نوشتن یک بایت** + پرامپت تعمیر دقیق (همان قرارداد نگهبان؛ `probe_reject` به وب). هشدارها (استایل جاافتاده که کف طراحی خودش پرش می‌کند، اسکریپت جاافتاده‌ی صفحه‌ی ایستا، کلاس بی‌استایل، عکس شکسته) اعمال می‌شوند و به دور فیکس می‌روند.
- **پراب دودتست (اجرای واقعی)**: فایل‌های ورودیِ تازه واقعاً اجرا می‌شوند — stdin بسته، مهلت ۸ ثانیه، خروجی کپ، و اگر سندباکس روشن باشد داخل همان سندباکس بی‌شبکه. طبقه‌بندی هرگز اشتباه نمی‌گیرد: کرش → خطای دقیق (آخرین خط استثنا با نام کلاس)، اسکریپت تعاملی (`input()`) → «info، کرش نیست»، سرور (`app.run`/`uvicorn`/`createServer`) → «بالا آمد و ماند»، حلقه‌ی بی‌پایان → هشدار.
- **پراب مرورگر بی‌سرباز (وقتی Playwright نصب باشد — کاملاً آفلاین با `file://`)**: خطاهای کنسول، استثناهای صفحه و منابع لود-نشده جمع می‌شوند و سپس **تا ۸ دکمه‌ی دیدنی واقعاً کلیک می‌شوند** — کرشِ لحظه‌ی کلیک = قابلیت مرده، گرفته شد. نبودِ Playwright = ردِ محترمانه؛ کف آفلاین همان پراب سیم‌کشی است.
- **پراب تکمیل‌بودن («بخشی از کار افتاد»)**: درخواست کاربر + **اسکلت قطعیِ** فایل‌های تحویلی (idها/دکمه‌ها/توابع — واقعیت نه حس‌وحال) به مغز لوکال می‌رود (هرگز کردیت ابری): «چه چیزی از خواسته غایب است یا رفتاری ندارد؟» هر gap یک یافته برای دور بعدیِ فیکس. مشاوره‌ای است — هرگز رد نمی‌کند.
- **فلسفه**: دروازه فقط بی‌ابهام‌ها را رد می‌کند تا بسته‌ی سالم هرگز قربانی نشود (مجموعه‌ی ۲۰۴۷تایی شامل بسته‌های چندفایلی design/fonts/edit-run این را اثبات می‌کند)؛ بسته‌ی دکمه‌مرده‌دار هرگز به دیسک نمی‌رسد. **درستی هرگز به اینترنت، مرورگر یا کردیت وابسته نیست.**
- **کنترل کامل**: فرمان `/probe` (وضعیت | on/off | wiring | smoke | browser | review | reject | reset) + کارت «شکارچی باگ» در تب مدل‌های وب با ۶ کلید + بلوک probe در `/api/info` و `/api/settings`؛ تنظیمات `.nova/probe.json`. کلیدهای اضطراری: `NOVA_PROBE=0` (کل)، `NOVA_PROBE_RUN=0`، `NOVA_PROBE_BROWSER=0`.
- **۵۵ تست جدید** (`test_v850_bug_hunter.py` — شامل اجرای واقعی مرورگر بی‌سرباز و کلیک دکمه در محیط تست) + همگام‌سازی ۴۶ پین نسخه در ۳۰ فایل تست + پارک شکارچی در تست‌های شمارش-کال v750/v820 | کل مجموعه: **۲۰۴۷/۲۰۴۷ سبز**.

- **هر زیرایجنت چهار لایه‌ی قطعی دارد** (همیشه آفلاین): ① پارسر واقعی که پایتون مجانی می‌دهد (ast/json/yaml/tomllib) ② ابزارهای parse-only نصب‌شده روی ماشین شما — `node --check`، `bash -n`، `php -l`، `ruby -c`، `gofmt -e`، `luac -p`، `gcc -fsyntax-only` (هرکدام ساب‌پروسس با تایم‌اوت و فیلتر «فقط خطای سینتکس» تا خطای تایپ‌چک بسته‌ی سالم را رد نکند) ③ **اسکنر براکت آگاه‌به-رشته/کامنت** با شماره‌ی خط — رشته‌ها، کامنت‌ها و بدنه‌ی heredoc برای هر خانواده‌ی زبانی فهمیده می‌شوند و هیچ‌وقت خطای واهی تولید نمی‌کنند ④ بانک الگوی باگ‌های رایج پرسیگنال (print پایتون۲، انتساب در شرط C، `else if` بشی، `gets()`، تایپوی `fmt.PrintIn` و…).
- **قرارداد اتمیک**: هر خطای قطعی = کل بسته رد می‌شود، **حتی یک بایت نوشته نمی‌شود**، لیست دقیق فایل/خط/مشکل چاپ و به وب هم ارسال می‌شود (`guardian_reject`) و یک **پرامپت تعمیر** با پروتکل `=== FILE: ===` ساخته می‌شود که در پیام بعدی خودکار به مدل تزریق می‌شود — یک «درستش کن» ساده هم دقیق اجرا می‌شود.
- **بازبینی معنایی پس از اعمال**: بعد از نوشتن فایل‌ها، زیرایجنت‌های زبانی **موازی** (روی موتور `nova_subagent`، فقط مغز لوکال — هرگز کردیت ابری) تا ۲ فایل را بازبینی می‌کنند (اسم تعریف‌نشده، API غلط، باگ منطقی) و یافته‌هایشان وارد `last_feedback["guardian"]` می‌شود که حلقه‌های `/auto`، `/verify` و `/fix` در دور بعدی می‌بینند.
- **وب‌سرچ اختصاصی، نه وابستگی**: ناوگان کانال جستجوی خودش را دارد — کش جدا با نیم‌اسپیس `guardian:` (با کش `/search` قاطی نمی‌شود)، بودجه‌ی زمانی سخت ۸ ثانیه (`NOVA_GUARDIAN_WEB_TIMEOUT`)، سقف ۲ کوئری در هر بازبینی. جوابش فقط پرامپت زیرایجنت‌ها را **غنی** می‌کند؛ **درستی هیچ‌وقت شرطش نیست** — بی‌اینترنت، **دانش‌نامه‌ی داخلی** هر زبان (که داخل ماژول سوار است) جایگزین می‌شود. `NOVA_GUARDIAN_WEB=0` هم کل اینترنت ناوگان را خاموش می‌کند.
- **کنترل کامل**: فرمان `/guardian` (وضعیت | on/off | model on/off | web on/off | reject on/off | `langs` فهرست زبان‌ها | `audit` پویش کل پروژه | reset) + کارت «نگهبان کد» در تب مدل‌های وب با ۴ کلید و نمایش ابزارهای شناسایی‌شده؛ تنظیمات در `.nova/guardian.json`. کلید اضطراری `NOVA_GUARDIAN=0` همه‌چیز را به رفتار قبلی برمی‌گرداند و نبودِ خود ماژول هم فقط یعنی «دروازه‌ی قدیمی» — صددرصد fail-soft.

## 🧠 نسخه ۷.۱۴.۰ — پروتکل THINK: تفکر قابل مشاهده برای هر مغز + ممیزی کلمه‌به‌کلمه

> «برای هوش‌هایی که استدلال دارند یک === THINK === / === END === بساز که متنشان را همان‌جا بنویسند که درباره‌ی چه و چطور فکر می‌کنند؛ و حتی مدل‌های بدون استدلال را مجبور به استدلال کن»

همه در یک هسته‌ی جدید (`app/nova_think.py`، کاملاً محلی):

- **بلوک تفکر استاندارد برای همه**: هر مغز قبل از پاسخ، در `=== THINK === ... === END ===` می‌نویسد چه و چطور فکر می‌کند. ترمینال همان لحظه می‌بیند؛ وب یک **جعبه‌ی جمع‌شونده** دارد که موقع فکر کردن باز است («در حال فکر کردن...») و بعد خودش جمع می‌شود — در **هر دو تب** کدنویسی و گفت‌وگو.
- **استدلال اجباری برای مدل‌های بدون استدلال**: qwen2.5-coder، llama و امثال‌شان یک یادداشت کوتاهِ ~۹۰ توکنی می‌گیرند که پروتکل را یادشان می‌دهد — «تفکر در ابر»، همان ترفندی که به مدل‌های کوچک کیفیت واقعی می‌دهد.
- **مدل‌های استدلال‌گر هم پشتیبانی می‌شوند**: deepseek-r1 / QwQ / qwen3 / o1-o3 / phi-4-reasoning و… خروجی `<think>` بومی‌شان به همان بلوک قابل مشاهده تبدیل می‌شود — همه‌ی مغزها یک شکل.
- **تفکیک تمیز**: تفکر هرگز فایل نمی‌شود، توکن ابزار نمی‌زند و وارد تاریخچه (رژیم کانتکست) نمی‌شود؛ حافظه فقط پاسخ تمیز را نگه می‌دارد. بلوک نیمه‌کاره هرگز «پاسخ» حساب نمی‌شود.
- **کنترل کامل**: `/think auto` (پیش‌فرض: فقط مدل‌های بدون استدلال بومی) | `/think on` (همه) | `/think off` — ثبت per-workspace؛ `NOVA_THINK=0` کلید خاموش سراسری.
- **امنیت پروتکل**: نشانگر THINK یا `<think>` داخل بدنه‌ی `=== FILE:/EDIT:` هرگز فایل را نمی‌بلعد (سه حمله‌ی واقعی، اجرا و اثبات و رفع شد — حتی «END فایل» توسط استخراجِ تفکر بومی حفظ می‌شود).

**ممیزی کلمه‌به‌کلمه — ۱۴ باگ اثبات‌شده و رفع‌شده** (هر کدام اجرا، اثبات، رفع و پین شد — جدول کامل در `FIXES-7.14.0.fa.md`): از «نثر چت داخل فایل نوشته می‌شد» (فقط برای مدل‌های استدلال‌گر!) و «بلوک KB مرده در Context Engine» و «داده‌ی خاموش به‌خاطر خطای رشته‌ای atomic» تا «مسابقه‌ی tmp در فروشگاه رمزشده» و «rescan بی‌دلیل ۴۰۰۰ فایل بعد از هر ری‌استارت» و «`/quit now` که استریم وب را می‌کشت».

**آزمون:** ۶۶ پین جدید (`test_v7140_think.py` + `test_v7141_audit_fixes.py`) | **۱۷۲۳ سبز** | **عملی زنده ۳۰/۳۰**: سرور واقعی + مغز ماک: ساخت پروژه‌ی چندفایلی **کافی‌شاپ** با بلوک THINK → اعمال واقعی → **عکس قبل** → نوبت ادیت (منوی کارتی + فیلتر + انیمیشن + hero گرادیانی) باز هم با THINK → **عکس بعد** — همه از طریق خط لوله‌ی واقعی نوا (`scripts/live_test_v7140_coffee.py`).
- جزئیات کامل: `FIXES-7.14.0.fa.md`

## 🧠 نسخه ۷.۱۳.۰ — «نوا هوش»: هوش پروژه یکپارچه، حافظه معنایی و حلقه عامل صادقانه

همه‌ی خواسته‌های فهرست هوشمندی در یک هسته‌ی جدید (`app/nova_intel.py`، کاملاً محلی و آفلاین) پیاده یا تقویت شد:

- **Project Intelligence واقعی و یکپارچه** — یک اسکن واحد (`/intel`): زبان‌ها، فریم‌ورک‌ها، نقاط ورودی، محل تست‌ها، نمادهای هر فایل (AST پایتون + ریجکس JS) و **گراف ایمپورت داخلی** (ایمپورت نقطه‌ای و نسبی هم حل می‌شود) در `.nova/intel.json` با اثر انگشت تغییر — بعد از هر تغییر فقط در صورت نیاز دوباره اسکن می‌شود.
- **Task Graph واقعی با وابستگی** — `/tasks`: DAG واقعی با `deps`؛ وظیفه‌ای که پیش‌نیازش تمام نشده «مسدود» است و هرگز در «آماده» نمی‌آید؛ ترتیب توپولوژیک، تشخیص حلقه (با رد کردن لبه‌ی مخرب)، dependents تراگذری (`/tasks impact t1`) و پیشرفت درصدی.
- **Memory معنایی، نه تاریخچه** — `/mem`: فروشگاه برداری TF-IDF دوزبانه (فارسی با فولد ZWNJ و ارقام فارسی) با بوست تازگی؛ «مشکل ورود کاربر» رکوردِ «قفل شدن کاربر بعد از پنج تلاش» را با معنا پیدا می‌کند؛ dedup، سقف ۶۰۰ رکورد، fail-soft با فایل خراب.
- **Context Engine** — `/ctx <پرسش>`: دقیق‌ترین کانتکست از ۵ منبع (وظایف، پروژه، حافظه، KB، تصمیم‌ها) با بودجه‌ی کاراکتر و اولویت ثابت؛ بلوکی که جای خود را نمی‌برد حذف می‌شود.
- **Agent Loop خودمختار** — `/loop <هدف>`: ماشین فاز پایدارشده (persisted) مشاهده ← تصمیم ← اجرا ← تست ← رفع ← تایید؛ هر گذار با «چرا» در `.nova/agent_runs/` ثبت و به داشبورد زنده آینه می‌شود.
- **تشخیص پایان کار و جلوگیری از موفقیت کاذب** — CompletionDetector: ادعای «تمام» فقط با حداقل یک مدرک واقعی (لینت/تست/اجرا) پذیرفته می‌شود؛ وگرنه **صادقانه failed** با دلیل ثبت می‌شود (استثنا فقط با waived + دلیل).
- **Recovery/Retry هوشمند** — طبقه‌بندی خطا (نحو/ایمپورت/تست/تایم‌اوت/شبکه/...) و نردبان پویش قطعی: retry → fix_targeted → split → rollback → stop، بدون بک‌آف تصادفی (تست‌پذیر).
- **Impact Analysis قبل از تغییر** — `/impact <فایل>`: چه فایل‌هایی (تراگذری) این فایل را ایمپورت می‌کنند، چه نمادهایی دارد و کدام فایل تست آن را پوشش می‌دهد.
- **Regression Detection بعد از تغییر** — `/regress baseline|check`: مقایسه‌ی صادقانه‌ی قبل/بعد؛ نتیجه‌ی تست همان گیتِ اعمال بدون اجرای دوباره استفاده می‌شود؛ verdict های new-fail/fixed/stable/no-tests.
- **تولید خودکار تست** — `/gentests <فایل>`: اسکلت pytest از AST (پینِ وجود + smoke های skip-شونده) و stub های node:test برای JS — هرگز روی فایل موجود نمی‌نویسد و اسکلت‌ها واقعاً اجرا می‌شوند.
- **Self-review مرحله‌ای** — `/critic`: چهار ایستگاه (protocol/syntax/impact/tests) + امتیاز ۰-۱۰۰ + حکم ship/fix/rollback؛ در وب بعد از هر اعمال خودکار چاپ می‌شود.
- **Rollback هوشمند** — تصمیم rollback + مکانِ آخرین snapshot (بازگردانی همان `/undo` قبلی می‌ماند تا یک نویسنده داشته باشیم).
- **چند پروژه مستقل** — `/workspaces`: ثبت/جابجایی/حذف پروژه‌ها (رجیستری در `~/.nova`، قابل تغییر با `NOVA_HOME`)؛ هر پروژه `.nova/` خودش را دارد و حافظه/وظایف/هوش بین پروژه‌ها نشت نمی‌کند.
- **پروفایل پروژه + کاربر** — پروفایل پروژه از اسکن + سرآیند NOVA.md/README؛ پروفایل کاربر (prefs + facts) ماندگار.
- **بهینه‌سازی مدل کوچک** — Context Engine بودجه‌دار + نردبان recovery + پروتکل‌های فشرده، دقیقاً برای مغزهای 1.5B-4B طراحی شده‌اند؛ همه‌چیز لوکال-اول می‌ماند.
- **داشبورد زنده وضعیت عامل** — تب جدید «هوش» در وب: الان چه می‌کند/چرا/قدم بعدی/چه چیزی تست شده + رویدادها، برد وظایف با دکمه‌های وضعیت، حافظه معنایی (یادگیری/بازیابی)، پروفایل پروژه و پسرفت — نوسازی خودکار هر ۱۵ ثانیه. API: `GET /api/intel` + `POST /api/intel` (۱۲ اکشن).
- **اتصال به خط لوله واقعی** — بعد از هر اعمال: تحلیل تاثیر (هشدار [impact])، امتیاز منتقد ([critic])، کتاب‌داری پسرفت، رکورد حافظه و آینه‌ی وضعیت زنده — همه fail-soft و داخل همان گیت کیفیت قبلی.
- **آزمون:** ۱۳۱ پین جدید (نمونه‌سازی، حافظه، گراف، کانتکست، حلقه، بازیابی، تاثیر، پسرفت، تولید تست، منتقد، rollback، وب و UI) | **۱۶۵۷ سبز ×۳** | **آزمون عملی زنده ۳۷/۳۷** (سرور واقعی + مغز ماک: چرخه‌ی کامل کدنویسی → قلاب‌های هوش → داشبورد + حلقه‌ی `/loop` درون‌فرایندی با پایانِ دارای مدرک).

## ⚡ نسخه ۶.۸.۳ — تقویت واقعی قدرت کدنویسی پنل وب

- **ویرایش چسبنده**: بلاک‌های `=== EDIT:` با فاصله/تورفتگیِ کمی متفاوت دیگر رد نمی‌شوند — تطبیق خط‌به‌خطِ مت tolerant (یک‌بار، و فقط اگر تطبیق یگانه باشد) در اعتبارسنجی، پیش‌نمایش پنل و اعمال؛ تطبیق مبهم همچنان رد می‌شود

- **اجرای سالم‌تر**: stdin فرزندها DEVNULL شد (برنامه‌ی `input()`‌دار دیگر هنگ نمی‌کند؛ پیام راهنمای فارسی/انگلیسی می‌گیرد) + `PYTHONUTF8=1` (خروجی فارسی روی ویندوز دیگر با UnicodeEncodeError کرش نمی‌کند)
- **لینت CSS**: توازن `{ }` و خالی‌نبودن قوانین قبل از نوشتن بررسی می‌شود — استایل‌شده‌ی ناقص دیگر ذخیره نمی‌شود
- پرامپت سخت‌گیرانه‌تر: «همه‌ی فایل‌ها در همین پاسخ» + «بدون fence داخل بلاک»

## 🌟 نسخه ۶.۷.۰ — ممیزی عمیق سوم: تک‌تک فایل‌ها خوانده شد و ~۴۵ باگ تازه رفع شد

در این نسخه یک دور **بازبینی خط‌به‌خط همه‌ی فایل‌ها** (از nova.py تا آخرین ماژول‌ها + لایه وب + بسته‌بندی) انجام شد و تمام یافته‌ها با تست اثبات شده و یکی‌یکی رفع شدند:

- 🔴 **بحرانی — جستجوی وب از v6.5 کاملاً مرده بود!** فیکس SSRF همان نسخه با یک اشتباه ظریف همراه بود: کلاس اتصال HTTPS متد `connect` را از کلاس HTTP قرض می‌گرفت و `super()` داخل آن به کلاس اشتباه اشاره می‌کرد — یعنی **هر fetch وب با TypeError می‌مرد**. `/search`، `/learn` و `[SEARCH:]` حالا دوباره کار می‌کنند
- 🛡 **بحرانی — دو دور زدن واقعی غربالگر فرمان بسته شد**:
  - `sh -c "rm -rf /"` و `powershell -Command "Remove-Item ... C:\"` — محتوای داخل کوتیشن دوبلِ مفسرها «کد زنده» است نه پیام؛ قبلاً ماسک می‌شد و **allow** می‌گرفت. حالا یک نسخه‌ی بدون ماسک هم غربال می‌شود
  - `echo "a\\" && rm -rf /` — بک‌اسلش دوبل، کوتیشن بستن را می‌بلعید و **کل دنباله‌ی فرمان از دید غربالگر ناپدید می‌شد**
  - `rmdir -Recurse -Force C:\` و alias های `del/rd/rm` در PowerShell حالا مثل خود `Remove-Item` به‌عنوان حذف ریشه‌ی درایو **deny** می‌شوند
- 🔫 **`/bg kill` دیگر پروسه‌ی بی‌گناه را نمی‌کشد**: اگر Nova کرش کرده باشد و OS آن PID را به برنامه‌ی دیگری داده باشد، فرمان kill اول **هویت** پروسه را با فرمان ثبت‌شده تطبیق می‌دهد (از `/proc` در لینوکس و image name در ویندوز)؛ در صورت عدم تطابق هیچ سیگنالی زده نمی‌شود
- 💾 **`/snapshot` + `/restore` حالا بایت‌به‌بایت دقیق است**: فایل‌های متنی CRLF (ویندوزی) به LF تبدیل و فایل‌های non-UTF-8 به U+FFFD تبدیل می‌شدند — بعد از restore کل پروژه جلوی چرت git تغییرکرده به‌نظر می‌رسید. حالا line ending ها و انکودینگ‌های غیر UTF-8 دست‌نخورده برمی‌گردند

## 🌟 نسخه ۶.۲ — آماده‌ی exe (بسته‌بندی ویندوز + تم شیشه‌ای کهکشانی)

### 🚀 ساخت فایل اجرایی ویندوز (.exe)

حالا پروژه **exe-ready** است؛ در پوشه `app` فقط دو مرحله:

```bat
pip install pyinstaller
build_exe.bat
```

نتیجه در `dist\NovaAssistant\`:
- **`NovaAssistant.exe`** — بدون کنسول (windowed). دابل‌کلیک کنید: داشبورد وب روی `127.0.0.1` بالا می‌آید و مرورگر خودش باز می‌شود. هر آرگومانی هم بدهید مثل `nova_assistant.py` عمل می‌کند (voice / photo / pixel / flow / ...).
- **`novacode.exe`** — نسخه کنسولیِ همان ایجنت؛ برای ترمینال کلاسیک (REPL، `--list-models`، `serve` با Ctrl+C).
- `web\` — چهره وب به‌صورت data داخل باندل هست؛ اگر نبود، برنامه به‌صورت خودکار `web\` کنار exe را پیدا می‌کند (`_resolve_web_dir`) — یعنی بدون rebuild فقط با عوض کردن آن پوشه می‌توانید UI را به‌روز کنید.
- **`local\`** کنار exe ساخته می‌شود: مدل‌های GGUF را همین‌جا بریزید (`local\code`، `local\voice`، `local\photo` برای دسته‌بندی). موقع frozen بودن، ریشه `local/` عمداً **کنار exe** لنگر می‌اندازد نه داخل پوشه موقت `_MEIPASS` که با هر اجرا پاک می‌شود.

نکته‌ها:
- PyInstaller فقط **ابزار build** است؛ خروجی همچنان وابستگی صفر دارد.
- روی `/run` و دستورهای پس‌زمینه و llama-server، فلگ `CREATE_NO_WINDOW` تنظیم شده تا در exe بدون کنسول، پنجره سیاه cmd برای هر دستور باز و بسته نشود.
- آیکون برنامه (`build_assets\NovaAssistant.ico`) با اسکریپت خودمان و بدون هیچ وابستگی‌ای تولید می‌شود (`scripts\make_icon.py`) — همان نشان جرقه‌ای کهکشانی، ۲۵۶×۲۵۶.
- دو exe از یک spec ساخته می‌شوند (`NovaAssistant.spec`): داشبورد windowed + ایجنت کنسولی، هر دو با یک آیکون.

### ✨ تم جدید وب (کاملاً CSS، بدون JS اضافه)

- آسمان پرستاره‌ی سه‌لایه با چشمک‌زدن نرم (فقط انیمیشن opacity = بدون فشار به CPU/GPU ضعیف) + سحابی چندلایه.
- فضای مرده‌ی گوشه‌ها پر شده: سیاره، موشک و دنباله‌دار پیکسلی — همه `pointer-events:none` و `aria-hidden` تا هیچ‌وقت مزاحم کلیک و اسکرین‌ریدر نباشند.
- خط درخشان متحرک باریک زیر هدر و بالای کامپوزر + تیتر گرادیانی با فال‌بک امن (`@supports`) که در مرورگرهای قدیمی نامرئی نمی‌شود.
- همه‌ی انیمیشن‌ها زیر `prefers-reduced-motion` خاموش می‌شوند؛ در موبایل هم تزئینات حذف می‌شوند.

## 🌟 نسخه 6.1 — پوشه‌های مدل دسته‌بندی‌شده + موتورهای صوتی جدید

### 📁 پوشه‌های مدل: هر بخش، مدل‌های خودش
مدل‌های فایلی حالا **دسته‌بندی‌شده** هستند — هر ماژول فقط مدل‌های دسته‌ی خودش (و مدل‌های عمومی) را می‌بیند:

```
local/                 ← مدل عمومی (GGUF): همه بخش‌ها می‌توانند استفاده کنند
├── code/              ← فقط Nova Code و Flow (LLM کدنویسی)
├── voice/             ← فقط Nova Voice (فایل‌های .onnx پیپر، مدل‌های صوتی)
└── photo/             ← فقط Nova Photo (چک‌پوینت‌های .safetensors برای A1111/ComfyUI)
```

- پوشه‌ی `local/` کنار خود برنامه ساخته می‌شود (در اولین اجرا، همراه با زیرپوشه‌ها و README راهنما)؛ همین الگو روی **هر** ریشه‌ی مدل هم کار می‌کند: `NOVA_MODELS_DIR`، `~/.nova/models` و `<workspace>/.nova/models` — مثلاً `~/.nova/models/voice` هم شناخته می‌شود (مستعارها: `tts/stt/speech` برای صدا، `image/img/art` برای تصویر، `coding/coder` برای کد).
- **Nova Flow همه پوشه‌ها را می‌بیند** (هاب یکپارچه).
- **مدل‌های Ollama نیاز به پوشه ندارند** — مستقیم از کتابخانه Ollama خوانده می‌شوند و همه بخش‌ها می‌توانند ازشان استفاده کنند.
- **اعتبارسنجی در لحظه تخصیص**: اگر مدل `local/photo` را به Nova Voice بدهید، خطای تمیز می‌گیرید («این مدل در پوشه photo است...»)، نه کراس در زمان اجرا. مدل‌های خراب/غیرقابل اجرا هم در تخصیص رد می‌شوند.
- برچسب دسته در جدول `/model` و `--list-models` نمایش داده می‌شود (`[code]`، `[voice]`، `[photo]`) و تب «مدل‌ها»ی وب فهرست مدل هر ردیف را فقط با دسته‌ی همان ماژول پر می‌کند + کادر «پوشه مدل‌ها» مسیرها را نشان می‌دهد.
- هوش اصلی ایجنت هنگام انتخاب خودکار، مدل‌های `general` و سپس `code` را ترجیح می‌دهد و اگر مدلی از پوشه voice/photo انتخاب کنید هشدار می‌دهد.

### 🔊 موتورهای صوتی جدید (Nova Voice)
- **`coqui`** — سرور Coqui TTS و Mozilla TTS (`POST /api/tts`) — هر دو با یک شکل API
- **`bark`** — bark-server (`POST /v1/generate`، Suno Bark لوکال)
- **Piper + پوشه voice**: مدل پیپر می‌تواند `file:<name>` باشد — مسیر .onnx از `local/voice` خودکار حل می‌شود؛ دادن یک GGUF به پیپر خطای واضح می‌دهد.

### 🧩 Flow: مغز فایلی
گره‌های LLM جریان کار حالا بک‌اند `file:` را **واقعاً** پشتیبانی می‌کنند (در v6.0 فقط در spec بود): اول وارد Ollama می‌شود (یک‌بار، کش‌شده)، اگر نشد llama-server روی پورت آزاد بالا می‌آید.

### 🖧 پریست‌های پلتفرم بیشتر
`ollama-openai` (endpoint سازگار-با-OpenAI خود Ollama)، `koboldcpp`، `text-generation-webui (tgwebui)`، `jan`، `gpt4all` — در کنار پنج پریست قبلی.

- **`/api/models_all` هیچ‌وقت مدل فایلی نشان نمی‌داد**: آرگومان‌های `scan_dirs` از حالا تایپ خارج شده بود و `TypeError` بی‌صدا خورده می‌شد — فهرست `file:` در کشوی وب و CLI از v6.0 عملاً خالی بود

- وب: سازنده گام‌به‌گام + اجرای نمونه آماده «idea-to-art»؛ ترمینال: `/flow list|run|show|del`

### 📚 Nova Knowledge
مغز سند محلی (الگوی AnythingLLM/PrivateGPT — بدون embedding و بدون vector DB): خوردن متن/کد با چانک‌بندی همپوشان، جستجوی **TF-IDF با توکنایزر فارسی-آگاه**، بسته‌ی زمینه آماده پرامپت، مقاوم به کرش (نوشتن اتمیک + تحمل خط ناقص). وب: تب دانش؛ ترمینال: `/knowledge ingest|search|stats|reset` — قابل استفاده در گره `knowledge` جریان‌ها.

## 🌟 نسخه 5.2 — Nova Assistant + مدل‌های فایلی (دو روش انتخاب مغز لوکال)

از این نسخه، نام برنامه **«Nova Assistant»** است و بخش کدنویسی آن **«Nova Code»** — در بنر ترمینال، رابط وب، PWA و نصب‌کننده‌ها. launcher جدید `nova` (و `nova.bat`) اضافه شده؛ `novacode` قبلی همچنان کار می‌کند (همان برنامه).

و مهم‌ترین قابلیت: **دو راه برای دادن مغز لوکال — هر دو از داخل خود برنامه قابل انتخاب‌اند:**

### روش ۱ — مدل‌های نصب‌شده در Ollama (مثل v5.1)
هر مدلی که با `ollama pull` نصب شده باشد هنگام شروع با `/api/tags` کشف می‌شود؛ جدول `/model` با شماره ردیف و مشخصات، منوی کشویی وب و `--list-models` همه از همین منبع پر می‌شوند.

### روش ۲ — فایل‌های مدل دانلودشده در پوشه مدل‌ها (جدید)
فایل‌های **GGUF** که خودتان دانلود کرده‌اید (مثلاً از Hugging Face) را در یکی از این پوشه‌ها بگذارید:

- `NOVA_MODELS_DIR=/path/to/folder` — هر پوشه‌ای که بگویید (با `os.pathsep` چند پوشه)
- `~/.nova/models` — پوشه‌ی سراسری پیش‌فرض
- `<workspace>/.nova/models` — مخصوص همین پروژه

سپس:
- **کشف خودکار:** فایل‌ها با پارسِ هدر GGUF (فقط چند کیلوبایت اول — هرگز داده‌های وزن خوانده نمی‌شود) به‌همراه نام، معماری، کوانتیزیشن و طول زمینه شناسایی می‌شوند؛ فایل‌های چند-پاره (`-00001-of-00003.gguf`) یک مدل حساب می‌شوند؛ فایل‌های `.safetensors` هم فهرست می‌شوند ولی صادقانه «قابل اجرا نیست — به GGUF تبدیل کنید» می‌گیرند.
- **انتخاب:** در جدول `/model` بخش دوم «Local model files» با شماره‌گذاری پیوسته بعد از مدل‌های Ollama می‌آید (`/model 5` یا `/model file:my-model`)؛ در وب هم گروه دوم در همان منوی کشویی است.
- **اجرا — خودکار و یک‌بار برای همیشه:** وقتی مدلی فایلی انتخاب شود، Nova به این ترتیب عمل می‌کند: اگر Ollama در دسترس باشد، فایل را یک‌بار با `ollama create` وارد کتابخانه می‌کند (با نام تعیین‌شده مثل `local-qwen2.5-7b-a1b2c3` — نتیجه در `.nova/local_models.json` کش می‌شود و دوباره تکرار نمی‌شود)؛ اگر Ollama نبود ولی `llama-server` (llama.cpp) روی PATH باشد، سرور را روی یک پورت لوکال بالا می‌آورد و از API سازگار OpenAI حرف می‌زند؛ هیچ‌کدام نبود، پیام خطای تمیز با راهنما می‌گیرید. در خروج، سرور spawn شده بسته می‌شود.
- **حتی بدون Ollama:** اگر هیچ مدل Ollama نصب نباشد ولی فایل GGUF در پوشه باشد، Nova خودش همان را به‌عنوان مغز پیش‌فرض انتخاب می‌کند.
- **--list-models حالا هر دو منبع را نشان می‌دهد** و فقط وقتی هیچ‌کدام خالی باشد خطا می‌دهد.

## 🌟 نسخه 5.1 — آزادی مدل (حذف هوش مصنوعی سفارشی + کشف مدل‌های لوکال)

در این نسخه **بخش ساخت هوش مصنوعی شخصی‌سازی‌شده به‌طور کامل حذف شده است**: دیگر پوشه‌ی `nova-ai/`، فایل `Modelfile` و مدل از پیش ساخته‌ی `nova-code` وجود ندارد. Nova Code حالا یک ایجنت خالص است که می‌خواهد به یک برنامه‌ی چند-بخشی تبدیل شود و ابزارها را در اختیار انواع هوش مصنوعی‌ها بگذارد؛ پس مغز، هر مدلی است که **خودتان** با Ollama نصب کنید:

- **کشف خودکار مدل‌ها:** هنگام هر اجرا، Nova تمام مدل‌های نصب‌شده‌ی Ollama را با یک فراخوانی `/api/tags` می‌خواند (نام، حجم روی دیسک، خانواده، تعداد پارامترها، کوانتیزیشن) و یک مدل کدنویسیِ مناسب را به‌عنوان پیش‌فرض انتخاب می‌کند — اولویت با مدل‌های کدنویس است (coder/code/…)، مدل‌های embedding هرگز خودکار انتخاب نمی‌شوند، و در تای‌ها نسخه‌ی سبک‌تر (۱.۵B قبل از ۷B) ترجیح دارد.
- **انتخاب مدل داخل ایجنت — `/model`:** بدون آرگومان، جدول کامل مدل‌های نصب‌شده با شماره‌ی ردیف، حجم و مشخصات را نشان می‌دهد و مدل فعلی را ستاره می‌زند. تعویض با **نام** (`/model qwen2.5-coder:7b`)، **نام پایه** (`/model qwen2.5-coder`) یا **شماره‌ی ردیف** (`/model 2`). نام مستعار: `/models`.
- **انتخاب مدل در وب:** منوی کشویی مدل در هدر صفحه‌ی وب (کنار نشان مغز) — با `GET /api/info` پر می‌شود و با `POST /api/settings {"model": "…"}` عوض می‌شود؛ نام نامعتبر با پیام فارسی رد می‌شود. معادل دستوری همان `/model` در کادر پیام است.
- **از خط فرمان:** `python3 nova.py --list-models` جدول مدل‌های لوکال را چاپ می‌کند و خارج می‌شود (اگر Ollama روشن نباشد خطای تمیز با راهنمای `ollama serve` / `ollama pull`).
- **اولویت تنظیم مدل:** پروفایل پروژه (`.nova/profile.json`) ← متغیر `NOVA_MODEL` ← تطبیق پایه‌ی `qwen2.5-coder` ← بهترین انتخاب خودکار. اگر مدل تنظیم‌شده روی ماشین نصب نباشد، Nova صادقانه هشدار می‌دهد و به بهترین مدل نصب‌شده سقوط می‌کند — هیچ‌وقت روی مدل ناموجود گیر نمی‌کند.
- **نصب‌کننده‌های جدید:** `install.sh` / `install.bat` دیگر مدلی نمی‌سازند؛ مدل‌های نصب‌شده را نشان می‌دهند و فقط اگر **هیچ مدلی** نباشد (یا با آرگومان صریح `./install.sh <model>`) یک مدل پایه را `pull` می‌کنند.
- **`/kb load <file>`:** چون کتاب دانش همراه حذف شده، این دستور حالا **هر فایلی** را که خودتان بگویید (نکات، چیت‌شیت، استانداردها) با مسیر امنِ داخل Workspace وارد پایگاه دانش می‌کند.

*(برای کاربران نسخه‌های قدیمی: مدل `nova-code` قبلی همچنان کار می‌کند — فقط یکی از مدل‌های نصب‌شده است؛ می‌توانید نگهش دارید یا با `ollama rm nova-code` حذفش کنید.)*

## 🌟 نسخه 5.0 — ابرساختار ایجنت (۲۰ قابلیت جدید)

نسخه 5.0 بیست قابلیت را به‌صورت یک لایه‌ی منسجم اضافه می‌کند. همان فلسفه‌ی همیشگی: **پایتون خالص، بدون dependency، صبور روی سخت‌افزار ضعیف**.

### نسخه‌بندی و تاریخچه
- **کامیت خودکار گیت + /undo نامحدود:** هر دسته‌ی اعمال یک unit دائمی در `.nova/snapshots/` می‌سازد؛ `/undo` حالا پله‌ای است (`/undo 3` سه دسته عقب می‌رود) و سقف «فقط آخرین تغییر» ندارد. اگر Workspace مخزن git باشد، هر اعمال **به‌صورت خودکار کامیت** هم می‌شود (پیام تولیدشده با پیشوند `nova:`؛ push هرگز اتفاق نمی‌افتد؛ `.nova/` با `.git/info/exclude` از مخزن دور می‌ماند).

- **تأیید تغییرات در وب:** دکمه‌ی «✎ تأیید» در هدر، حالت تأیید-قبل-از-نوشتن را روشن می‌کند؛ تغییرات به‌جای نوشتن، در پنلی با دیف رنگی و دکمه‌ی ✔/✖ برای هر هانک می‌نشینند و با «اعمال انتخاب‌شده‌ها» (POST `/api/apply`) اعمال می‌شوند — هانک‌ها در لحظه‌ی اعمال دوباره اعتبارسنجی می‌شوند.

## 🔒 نسخه 4.1 — هاردنینگ امنیتی و مقاوم‌سازی (گزارش کامل ممیزی)

نسخه 4.1 حاصل یک ممیزی کامل امنیتی/کیفیت است. مهم‌ترین تغییرات:

- **چهره وب ضد CSRF شد:** در حالت پیش‌فرض لوکال، هر POST حالا `Origin` هم‌مبدأ می‌خواهد، `Content-Type` باید `application/json` باشد و هدر `Host` باید نام همین ماشین باشد (ضد DNS-rebinding) — یعنی یک سایت خارجی دیگر نمی‌تواند بی‌صدا به `/api/run` دستور تزریق کند.
- **`--host ""` دیگر حفره نیست:** قبلاً روی همه‌ی کارت شبکه bind می‌شد ولی احراز هویت فکر می‌کرد لوکال است (ورود از شبکه بدون توکن!). حالا مقدار خالی رد می‌شود و bind/احراز هویت از یک مقدار واحد می‌خوانند.
- **گارد فایل‌های محرمانه:** `.env`، `.ssh/*`، `id_rsa`، `*.pem/key` و مشابه‌ها دیگر با `[READ:]`، `/load`، `/search`، `/learn` یا `/review` وارد کانتکست مدل نمی‌شوند (با provider ابری = نشت سکرت).
- **سندباکس مسیر مقاوم‌تر شد:** به‌علاوه‌ی همان محافظت قبلی در برابر `../`، حالا escape از طریق symlink داخل Workspace هم بسته شد و کاراکترهای کنترلی (NUL و…) در نام فایل پاک‌سازی می‌شوند.
- **`/serve` محافظت‌شده:** سرور پیش‌نمایش حالا داخل خود ایجنت اجرا می‌شود و فایل‌های مخفی (`.env`، `.git/`…) و هر مسیری که با symlink بیرون از Workspace برود را با 404 رد می‌کند.
- **صادقانه درباره‌ی `/run`:** دستورات shell فقط *پوشه‌ی کاری‌شان* Workspace است و با دسترسی کامل کاربر اجرا می‌شوند — سندباکس امنیتی نیست؛ متن راهنما/کد حالا همین را می‌گوید.
- **SSRF بسته شد:** `/docs` و fetch صفحه‌ها دیگر به `127.0.0.1`، LAN، link-local (169.254.x) و ریدایرکت‌ها به این مقصدها نمی‌روند (`NOVA_ALLOW_PRIVATE_FETCH=1` برای استثنا).
- **اصلاحات دقت:** پیوست‌های `/fix` و `/verify` دیگر دوبار ارسال نمی‌شوند؛ خط `Run:` از **آخرین** مورد *بیرون* از بلوک‌های فایل برداشته می‌شود (یک `run:` در Makefile دیگر دستور را نمی‌دزدد)؛ توکن‌های `[READ:]`/`[SEARCH:]` فقط وقتی *تنها روی یک خط* باشند اجرا می‌شوند و ترتیبِ متن ملاک است؛ پیام کاربر اگر از پنجره متن بزرگ‌تر باشد خودش کوتاه می‌شود؛ Ctrl+C وسط `/run` پروسه‌ی فرزند را می‌کُشد.
- **پروایدرها:** خروجی خراب/غیر استاندارد APIها به‌جای کرش، `ProviderError` تمیز می‌دهد؛ خطای شبکه هم همین‌طور؛ کلید Gemini از URL به هدر منتقل شد؛ `NOVA_BASE_URL` حالا فقط پروایدر `custom` را override می‌کند (تا کلید پروایدر ثابت به آدرس دیگری نشت نکند).
- **جستجو:** fallback گزیش ناقص حالا واقعاً اجرا می‌شود (EOFError)؛ snippet های DDG دیگر جابه‌جا روی نتیجه‌ی اشتباه نمی‌نشینند؛ صفحه‌ی خالیِ JS-only یک هفته کش نمی‌شود.
- **وب + اسکریپت‌ها:** پاسخ‌های خطا `Connection: close` می‌فرستند (بدون desync در keep-alive)؛ بستن تب وسط استریم، نوبت ایجنت را نمی‌کُشد؛ مقایسه‌ی توکن با ورودی غیر ASCII کرش نمی‌کند؛ `install.bat` (quoting + errorlevel + CRLF) و `install.sh` (امن زیر `curl | bash`) اصلاح شدند؛ لانچر `python` نسخه‌ی ۳ را واقعاً چک می‌کند.

## 🧠 نسخه 2.5 — مغز قوی‌تر مدل

نسخه 2.5 رفتار خود مدل `nova-code` را قوی‌تر کرده است (نه فقط ابزارهای اطرافش):

- **پرامپت سیستم بازنویسی شد** — همان متنِ دقیق هم در `Modelfile` و هم در ایجنت تزریق می‌شود (تلاش برای واگرایی صفر):
  - پروتکل `=== FILE: ===` حالا با یک **مثال عملی کامل** آموزش داده می‌شود — مدل‌های کوچک از مثال خیلی بهتر از توضیح یاد می‌گیرند
  - **قوانین زبانی**: Python (نقطه ورود، مدیریت خطا)، JavaScript (هرگز روی حرکت کاربر کرش نکند، ضد XSS)، HTML+CSS (واکنش‌گرا، آفلاین) و SQL (فقط پارامترِ `?`/`%s` — هرگز کوئری با چسباندن رشته؛ کلید اصلی و نوع درست ستون‌ها)
  - گردش‌کار «هسته کوچکِ قابل‌اجرا اول، بعد گام بعدی» برای پروژه‌های بزرگ تا فایل‌ها بریده نشوند
- **مدیریت پنجره متن (مهم‌ترین اصلاح):** اگر پرامپت از `num_ctx` بزرگ‌تر شود، llama.cpp بی‌صدا از «اولِ پرامپت» حذف می‌کند — یعنی قوانین پروتکل فایل از بین می‌رفت و جواب‌ها خراب می‌شد. حالا ایجنت خودش قبل از ارسال، به‌ترتیبِ کنترل‌شده کم می‌کند: قدیمی‌ترین تاریخچه ← پایگاه دانش ← نقشه فایل. قوانین اصلی و پیام فعلی شما هرگز حذف نمی‌شوند. اگر کم‌کردن اتفاق بیفتد این خط را می‌بینید:
  ```
  [context] trimmed old history / knowledge / file map to fit the 4096-token window
  ```
- **`num_predict = -1`** — بعضی نسخه‌های Ollama پاسخ را پیش‌فرض روی ۱۲۸ توکن محبوس می‌کنند و فایل نصفه تحویل می‌داد؛ حالا صریحاً بی‌نهایت شده و پاسخ طبیعی تمام می‌شود
- **پارامترهای بهینه‌شده**: `repeat_penalty` از 1.1 به **1.05** کاهش یافت (کد تکرار شناسه‌ها را لازم دارد؛ جریمه بالا مدل‌های کوچک را به خطای نحوی می‌کشاند) و `top_k 40` برای حذف انتخاب‌های عجیب انتهای توزیع اضافه شد
- **«continue» هوشمند:** بعد از یک پاسخ نصفه، تایپ `continue` دیگر به مدل واژه‌ی مبهم نمی‌دهد؛ ایجنت خودش دستور دقیق «از همان‌جا ادامه بده، چیزهای نوشته‌شده را تکرار نکن» را می‌سازد
- **چت وب:** صفحه وب حالا یک پرامپت سیستم مخصوص «چت ساده» می‌فرستد تا مدل در مرورگر بلوک خام `=== FILE: ===` تولید نکند و به زبان خود شما جواب بدهد

## 🔍 جستجو و یادگیری از وب (به‌روزرسانی دانش مدل)

مدل‌های کوچک محلی تاریخ قطع دارند و نسخه‌های جدید کتابخانه‌ها را نمی‌دانند. Nova Code سه راه برای به‌روزرسانی دانش خود دارد — همه بدون API key و فقط با منابع معتبر:

### دستورها

| دستور | کار |
|--------|-----|
| `/search <query>` | جستجو در وب؛ نتایج برچسب منبع دارند (`official` / `trusted` / `community` / `web`). با زدن شماره یا `a` (سه نتیجه برتر) محتوای صفحه به پیام بعدی شما پیوست می‌شود |
| `/learn <topic>` | **یادگیری عمیق**: تا ۳ صفحه از دامنه‌های مختلفِ معتبر را می‌خواند و خلاصه را در پایگاه دانش Workspace ذخیره می‌کند — از این به بعد در همه مکالمات همان پروژه به پرامپت سیستم تزریق می‌شود |
| `/docs <url>` | خواندن یک صفحه مستندات مشخص (آدرس کامل) و پیوست آن به پیام بعدی |
| `/kb` | مشاهده پایگاه دانش: لیست (`/kb`)، دیدن یک مدخل (`/kb show 2`)، پاک کردن (`/kb clear`) |

### جستجوی خودکار توسط خود مدل

اگر مدل وسط کار بفهمد اطلاعات به‌روز لازم دارد (مثلاً نسخه جدید یک کتابخانه)، در جوابش فقط این خط را می‌نویسد:

```
[SEARCH: express js 4 router params]
```

ایجنت خودش جستجو می‌کند، ۲ منبع معتبر برتر را می‌خواند و نتیجه را به مدل برمی‌گرداند تا جواب نهایی را با اطلاعات درست بدهد. در پرامپت سیستم مدل آموزش دیده که **هرگز شماره نسخه یا API را از خودش نسازد** و به‌جای دروغ گفتن، درخواست جستجو بدهد.

## 🔒 امنیت و اطمینان

- نوشتن فایل **فقط داخل Workspace** — مسیرهای `../` و مسیرهای مطلق مسدودند
- کاراکترهای غیرمجاز ویندوز در نام فایل‌ها پاک‌سازی می‌شوند
- بکاپ timestamp دار در `Workspace/.nova_backups/` قبل از هر بازنویسی؛ `/undo` کل آخرین دسته را برمی‌گرداند
- حلقه اصلی ایجنت در برابر خطاهای پیش‌بینی‌نشده مقاوم است (خرابی داخل یک دستور، نشست را نمی‌بندد)
- `/run` با مهلت زمانی (پیش‌فرض ۱۲۰ ثانیه، با `/timeout` تا ۳۶۰۰ قابل افزایش؛ متغیر `NOVA_RUN_TIMEOUT`) — سرورهای دائمی به `/serve` سپرده می‌شوند
- خروج از برنامه، سرور پیش‌نمایش را همیشه به‌صورت تمیز می‌بندد
- سرور پیش‌نمایش `/serve` و چت وب **به‌صورت پیش‌فرض فقط روی 127.0.0.1** اجرا می‌شوند — سایت و چت شما روی شبکه محلی (Wi-Fi کافه و…) دیده نمی‌شود؛ اگر خودتان با `--host` آدرس دیگری بدهید، ورود بدون توکن دسترسی مسدود می‌شود (به بخش «چهره وب» زیر مراجعه کنید)
- خروجی `/run` سقف حجم دارد (~۴۰۰ هزار کاراکتر برای هر جریان) — یک برنامه‌ای که بی‌نهایت خروجی چاپ می‌کند، رم ۴ گیگی را پر نمی‌کند
- اگر `/run` به مهلت زمانی بخورد، **کل درخت پردازه** کشته می‌شود (پردازه‌ی یتیمی در پس‌زمینه زنده نمی‌ماند و برنامه هرگز بی‌نهایت معطل نمی‌ماند)
- همه فایل‌ها با UTF-8 و پایان‌خط LF نوشته می‌شوند — فایل‌ها بین ویندوز و لینوکس/مک سالم و یکسان می‌مانند (اسکریپت‌های bash خراب نمی‌شوند)
- نام‌های رزرو ویندوز (CON، NUL، COM1 و…) به‌طور خودکار پاک‌سازی می‌شوند
- **جستجوی وب (وقتی فعال است):** فقط URLهای http/https ساده (بدون credential)؛ فقط خواندن متن صفحات، نه اجرای کد؛ سقف حجم هر صفحه ~۲MB و متن هر صفحه ~۱۵۰۰ کاراکتر؛ نتایج فقط به‌صورت متن به مدل می‌روند — هیچ کدی از وب مستقیم اجرا نمی‌شود؛ برای حذف کامل جستجو، فایل `nova_search.py` را کنار نگذارید یا اینترنت را قطع کنید

## 🌐 چهره وب — همان ایجنت، در مرورگر (v4.0)

```bash
cd app
./novacode --web             # لینوکس / مک  →  http://localhost:8765
novacode.bat --web           # ویندوز
```

قبلاً وب فقط یک «چت ساده» بود که مستقیم به Ollama وصل می‌شد. الان **دقیقاً همان ایجنت ترمینال** در مرورگر اجرا می‌شود:

- فایل‌های واقعی می‌سازد و در Workspace ذخیره می‌کند (چیپ‌های سبز/زرد = ساخته‌شده/ویرایش‌شده)
- همه‌ی ابزارها در کادر پیام کار می‌کنند: `/ls`، `/check`، `/kb`، `/learn`، `/model`، `/provider` و…
- یادداشت‌های کنسول ایجنت (جستجو، تغییر فایل، اجرای ابزار) زنده در صفحه جاری می‌شوند
- دستور `Run:` پیشنهادی با دکمه «▶ اجرا» می‌آید — **فقط با کلیک صریح شما** اجرا می‌شود
- مغز را همان‌جا عوض کنید: `/provider openai` — یا به مدل لوکال برگردید: `/provider ollama`
- به‌صورت پیش‌فرض فقط روی `127.0.0.1` سرو می‌کند (هیچ‌چیز روی شبکه دیده نمی‌شود)؛ اگر با `--host 0.0.0.0` (یا هر آدرس غیرِ محلی دیگر) اجرا کنید تا از دستگاه‌های دیگر شبکه هم در دسترس باشد، یک **توکن دسترسی** به‌صورت خودکار ساخته و در کنسول چاپ می‌شود؛ بدون آن توکن، صفحه و API باز نمی‌شوند. این توکن برای کل عمر همین اجرای سرور معتبر است (نه فقط یک بار) — با اولین ورود در یک کوکی مرورگر ذخیره می‌شود تا لازم نباشد هر بار در آدرس بنویسیدش؛ با هر بار اجرای دوباره‌ی `--web`، توکن تازه‌ای ساخته می‌شود و توکن‌های قبلی دیگر کار نمی‌کنند
- **از نسخه 4.1** حتی در حالت لوکالِ بدون توکن، درخواست‌های POST از مبدأ دیگر (سایت‌های خارجی) با چک `Origin` + الزام `Content-Type: application/json` + چک هدر `Host` (ضد DNS-rebinding) رد می‌شوند — یک صفحه‌ی مخرب در مرورگر شما نمی‌تواند بی‌صدا به ایجنت لوکال دستور بدهد؛ پاسخ‌های خطا هم اتصال را می‌بندند تا بدنه‌ی خوانده‌نشده باعث desync نشود
- تاریخچه گفتگو در همان مرورگر (به تفکیک Workspace) ذخیره می‌شود و با رفرش صفحه پاک نمی‌شود؛ دکمه 🗑 کنار نشانگر وضعیت آن را پاک می‌کند

تنها تفاوت با ترمینال: بدون حلقه‌های تعاملی (تأییدهای Y/n به‌صورت امن خودکار جواب می‌گیرند) و اجرای دستور با کلیک شما — بقیه یکی است: `novacode` و `novacode --web` روی یک Workspace و یک حافظه کار می‌کنند.

## 🛠 رفع اشکالات این نسخه

این دور، هفت مشکل مشخص در چهره وب رفع شد:

1. **تست‌های خودکار** — پوشه `app/tests/` اضافه شد (۵۰ تست، فقط با کتابخانه استاندارد پایتون، بدون نیاز به شبکه/Ollama). اجرا:
   ```bash
   cd app
   python3 -m unittest discover -s tests -v
   ```
   شامل: پارس آرگومان‌های خط فرمان، لایه پروایدرها (resolve/set_provider/parsing)، و سرور وب (احراز هویت، favicon، اعتبارسنجی درخواست‌ها، و کل مسیر استریم NDJSON با یک دستور اسلش واقعی).
2. **بررسی دوره‌ای اتصال** — صفحه وب هر ۱۵ ثانیه (و هر بار که تب دوباره دیده می‌شود) وضعیت را از `/api/info` می‌گیرد، نه فقط بعد از هر پیام.
3. **Favicon** — همان نشان پیکسلی هدر حالا از `/favicon.svg` و `/favicon.ico` هم سرو می‌شود.
4. **هماهنگی برند** — اموجی ✦ کنار نام «Nova Code» در حباب‌های پاسخ حذف و همان آیکون پیکسلی هدر جایگزین شد.
5. **`aria-live` برای screen reader** — یک ناحیه مخفی (`#sr-live`) فقط در پایان هر نوبت (نه هر توکن استریم) خلاصه پاسخ/خطا را اعلام می‌کند؛ نشانگر وضعیت اتصال `role="status"` و باکس خطا `role="alert"` گرفتند.
6. **احراز هویت روی `--host 0.0.0.0`** — توضیح کامل در بخش «چهره وب» بالا؛ بایند محلی (پیش‌فرض) دقیقاً مثل قبل بدون توکن کار می‌کند.
7. **حفظ تاریخچه چت بعد از رفرش** — پیام‌های نهایی کاربر/Nova در `localStorage` مرورگر (به تفکیک نام Workspace) ذخیره و در بارگذاری بعدی بازیابی می‌شوند؛ یادداشت‌های زنده ابزار/فایل (که فقط در همان نوبت معنا دارند) ذخیره نمی‌شوند.

هیچ‌کدام از این تغییرات به منطق Agent/Tool/Provider دست نزده‌اند؛ فقط لایه نمایش (`web/index.html`) و لایه سرور (`web_server.py`) عوض شده‌اند.

## 🐢 لپ‌تاپ ضعیف: مهلت‌ها، صبر و تنظیمات

روی سخت‌افزار ضعیف، پاسخ‌های Ollama ممکن است **خیلی خیلی طول بکشد**. Nova Code دقیقاً برای همین طراحی شده — فلسفه‌اش ساده است:

- **هیچ چیز پاسخ مدل را وسط کار قطع نمی‌کند.** مهلت‌هایی که در Nova وجود دارند فقط «سقف سکوت» هستند، نه سقف کل پاسخ: تا وقتی توکن‌ها می‌آیند، تولید تا هر چند دقیقه/ساعت ادامه پیدا می‌کند.
- **تایمر ضربان:** موقع انتظار، هر ۱۵ ثانیه خط `[waiting] Ns elapsed...` به‌روز می‌شود — یعنی برنامه زنده است. اگر Ctrl+C بزنید، پاسخ نیمه‌کاره نگه داشته می‌شود و می‌توانید بنویسید `continue` تا از همان‌جا ادامه دهد.
- **چرا اولین پاسخ کند است؟** قبل از اولین توکن، Ollama باید مدل را از دیسک بارگذاری کند و کل پرامپت را روی CPU پردازش کند — روی لپ‌تاپ ضعیف این می‌تواند چند دقیقه طول بکشد. توکن‌های بعدی خیلی سریع‌تر می‌آیند.
- **مدل در رم می‌ماند:** `keep_alive=60m` یعنی بعد از هر مکث (مثلاً ۱۰ دقیقه خواندن کد) مدل دوباره از دیسک بارگذاری نمی‌شود. برای آزادکردن رم بعد از کار: `ollama stop nova-code`.

### جدول کامل تنظیمات صبر

| تنظیم | پیش‌فرض | کار |
|--------|---------|-----|
| `NOVA_TIMEOUT` | `1800` | حداکثر سکوت مجاز بین دو توکن (ثانیه) — سقف کل پاسخ نیست |
| `NOVA_RUN_TIMEOUT` یا `/timeout` | `120` | مهلت اجرای دستور `/run` (۵ تا ۳۶۰۰ ثانیه) |
| `NOVA_NUM_CTX` | `4096` | اندازه پنجره متن — کمتر = رم کمتر، بیشتر = حافظه بیشتر |
| `NOVA_CTX_RESERVE` | `1400` | توکن‌های همیشه آزاد برای «جوابِ» مدل هنگام مدیریت پنجره متن (کمتر = تاریخچه بیشتری نگه داشته می‌شود) |
| `NOVA_KEEP_ALIVE` | `60m` | مدت ماندن مدل در رم بین پیام‌ها (`-1` = برای همیشه) |
| `NOVA_OLLAMA_URL` | `http://localhost:11434` | آدرس سرور Ollama |
| `NOVA_NOCOLOR` | `0` | با `1` رنگ‌های ترمینال خاموش می‌شوند |

### تنظیمات جستجوی وب

| تنظیم | پیش‌فرض | کار |
|--------|---------|-----|
| `NOVA_SEARCH_RETRIES` | `1` | تعداد تلاش مجدد هر درخواست وب (۰ تا ۵) |
| `NOVA_SEARCH_TIMEOUT` | `45` | مهلت هر درخواست وب (ثانیه — برای اینترنت کند زیادش کنید) |
| `NOVA_SEARCH_RESULTS` | `8` | تعداد نتایج `/search` |
| `NOVA_LEARN_PAGES` | `3` | تعداد صفحاتی که `/learn` می‌خواند |
| `NOVA_PAGE_CHARS` | `1500` | حداکثر متن ذخیره‌شده از هر صفحه |
| `NOVA_KB_CHARS` | `3000` | حداکثر محتوای پایگاه دانش تزریق‌شده به پرامپت |
| `NOVA_CACHE_DAYS` | `7` | مدت اعتبار کش (۰ = کش خاموش) |
| `NOVA_CACHE_DIR` | `~/.nova_cache` | محل کش جستجوها و صفحات |

مثال برای یک لپ‌تاپ خیلی ضعیف:

```bash
NOVA_NUM_CTX=2048 NOVA_TIMEOUT=3600 ./novacode
```

- رابط وب هم **بدون هیچ timeout** است و موقع انتظار، شمارنده ثانیه فارسی («مدل در حال فکر کردن است… ۴۵ ثانیه») نشان می‌دهد.
- روی ۴ گیگ رم: نصب‌کننده پایه ۱.۵B را پیشنهاد می‌دهد؛ برنامه‌های دیگر را ببندید؛ برای پاسخ اول چند دقیقه صبر کنید — کاملاً طبیعی است.

## ⚡ نکات سرعت

- `/mode code` دقیق‌ترین حالت است؛ برای ایده‌پردازی بصری `/mode creative`
- `/clear` بعد از تمام شدن هر پروژه — حافظه کوتاه‌تر = پاسخ سریع‌تر و دقیق‌تر

- پرامپت‌های کوتاه‌تر = پردازش اولیه سریع‌تر؛ `/clear` کمک می‌کند
- بعد از کار: `ollama stop <model-name>` تا رم آزاد شود

## 🧠 v4.0 — یک برنامه، دو چهره + مغزهای چندگانه (جدید)

سه تغییر بزرگ، بدون از دست دادن هیچ قابلیتی:

**۱) یک برنامه، دو چهره:** ترمینال و وب دیگر دو برنامه‌ی جدا نیستند. `novacode` چهره ترمینال است، `novacode --web` چهره وب — همان یک ایجنت، همان Session، همان ابزارها، همان پروتکل فایل و بکاپ. وب حالا ایجنت کامل است: فایل واقعی می‌سازد، ابزار اجرا می‌کند، یادداشت‌ها زنده جاری می‌شوند و دستورهای `Run:` با کلیک شما اجرا می‌شوند.

**۲) مغز قابل تعویض (`/provider`):** ایجنت حالا روی هر مدلی می‌نشیند:

| پروایدر | چه چیزی | کلید لازم |
|---------|---------|-----------|
| `ollama` (پیش‌فرض) | **هر** مدل Ollama که نصب کرده باشید — خودکار کشف می‌شوند (`/model`) | نداشت |
| `openai` / `openrouter` / `groq` / `deepseek` | ابر؛ OpenRouter صدها مدل با یک کلید | `OPENAI_API_KEY` / `OPENROUTER_API_KEY` / `GROQ_API_KEY` / `DEEPSEEK_API_KEY` |

## 💾 v3.2 — مدل بزرگ‌تر از رم؟ حالت دیسک + کیت صرفه‌جویی رم (جدید)

**سؤال: می‌شود مدل به‌جای رم از حافظه (دیسک) استفاده کند؟** پاسخ صادقانه: **تا حدی بله — و `/disk` دقیقاً همین را اندازه می‌گیرد.** اُلاما فایل مدل را با mmap از دیسک می‌خواند، پس مدلی بزرگ‌تر از رم هم اجرا می‌شود؛ اما فیزیک مسئله این است که برای تولید **هر توکن** باید همه‌ی وزن‌های مدل یک بار خوانده شوند. بخشی که در رم جا نشود، **برای هر توکن از دیسک دوباره خوانده می‌شود**. یعنی:

| کمبود رم | NVMe SSD | SSD ساتا | هارد دیسک |
|-----------|----------|-----------|------------|
| ۱ گیگ | ~۰.۷ ثانیه/توکن | ~۲.۵ ثانیه/توکن | ~۱۰ ثانیه/توکن |
| ۸ گیگ | ~۵ ثانیه/توکن (جواب ۳۰۰ توکنی ≈ ۲۷ دقیقه) | ~۲۰ ثانیه/توکن | غیرقابل استفاده |
| ۲۰+ گیگ | غیرقابل استفاده | غیرقابل استفاده | غیرقابل استفاده |

نتیجه: حالت دیسک برای **چند جمله امتحانی** جواب می‌دهد، نه تولید پروژه. رم همیشه سریع‌تر است — اول کیت صرفه‌جویی رم را امتحان کنید، بعد swap، بعد مدل کوچک‌تر.

### `/disk` چه کاری می‌کند؟

```
/disk
```

- رم واقعی سیستم (کل و آزاد) و فضای خالی دیسک را نشان می‌دهد
- **هر مدل نصب‌شده** را می‌سنجد: «در رم جا می‌شود (سرعت کامل)» / «تنگ است» / «دیسک‌بک»
- اگر مدلی دیسک‌بک باشد: برآورد سرعت به تفکیک نوع دیسک + دستورهای آماده‌ی swap (لینوکس) یا pagefile (ویندوز) چاپ می‌کند
- **کیت صرفه‌جویی رم اُلاما** را هم همیشه نشان می‌دهد (پایین) — Nova Code هیچ‌وقت خودش این دستورها را اجرا نمی‌کند؛ همه اختیاری و دستی هستند
- کاملاً fail-soft: بدون اُلاما و بدون تشخیص رم هم کار می‌کند

### کیت صرفه‌جویی رم (بدون افت محسوس کیفیت)

این سه متغیر محیطی روی **سرور Ollama** مصرف رم کش KV را تقریباً **نصف** می‌کنند:

| متغیر | کار |
|--------|-----|
| `OLLAMA_NUM_PARALLEL=1` | اُلاما به‌طور پیش‌فرض کش KV را برای چند درخواست هم‌زمان پیش‌تخصیص می‌کند — روی یک کاربر یعنی رم هدررفته |
| `OLLAMA_FLASH_ATTENTION=1` | حافظه‌ی محاسبه‌ی attention را کم می‌کند (پیش‌نیاز کش کوانتیزه در اکثر نسخه‌ها) |
| `OLLAMA_KV_CACHE_TYPE=q8_0` | کش KV را ۸ بیتی کوانتیزه می‌کند ≈ نصف حافظه؛ افت کیفیت روی مدل‌های کوچک نامحسوس |

ویندوز: `setx OLLAMA_NUM_PARALLEL 1` (و دو مورد دیگر) → از tray خارج و دوباره اجرا کنید. لینوکس (سرویس systemd): `sudo systemctl edit ollama` و افزودن `Environment="OLLAMA_NUM_PARALLEL=1"` و… زیر `[Service]` → `sudo systemctl restart ollama`.

دو اهرم سمت ایجنت هم همیشه در دسترس است:

- `NOVA_NUM_CTX=2048` — پنجره‌ی متن نصف می‌شود (مصرف رم KV نصف؛ برای پروژه‌های کوچک کافی است)
- `NOVA_KEEP_ALIVE=0` — مدل بین پیام‌ها از رم **تخلیه می‌شود** و فقط روی دیسک می‌ماند (پاسخ بعدی دوباره از دیسک بارگذاری می‌شود — شروع کندتر، رمِ بیکار آزاد)

### توصیه‌ی طلایی

- رم آزاد ~۴ گیگ: همان `qwen2.5-coder:1.5b`/`3b` + کیت صرفه‌جویی رم — بهترین نسبت سرعت/هوش
- رم آزاد ~۶–۸ گیگ: `ollama pull qwen2.5-coder:7b` (~۴.۴ گیگ) — **سرعت کامل، مغز بسیار قوی‌تر**؛ این از هر ترفند دیسکی بهتر است

## 🔁 v3.1 — حلقه‌های ابزار، ویرایش جراحی و وریفای خودکار

این نسخه دقیقاً سه خواسته را در Nova Code پیاده می‌کند — همان چیزهایی که یک ایجنت کلاس Claude واقعی را می‌سازد:

**۱) چرخه‌ی چندمرحله‌ای ابزار** — قبلاً مدل در هر پاسخ فقط **یک بار** می‌توانست توکن بخواهد (`[READ:]` یا `[SEARCH:]`). حالا می‌تواند **زنجیره‌ای** کار کند: اول محتوای فایل را ببیند `[READ: src/app.js]` → بعد برای اطمینان از API یک `[SEARCH: ...]` بزند → بعد فایل نهایی را بنویسد. هر نتیجه به مدل برمی‌گردد و ادامه می‌دهد. تعداد دورها با `NOVA_TOOL_ROUNDS` (پیش‌فرض ۳، حداکثر ۶) کنترل می‌شود و برای سخت‌افزار ضعیف سه محافظ دارد:

| محافظ | کارش |
|-------|------|
| محافظ تکرار | همان توکن با همان آرگومان هرگز دو بار اجرا نمی‌شود؛ مدل یک اخطار می‌گیرد و پاسخ را تمام می‌کند |
| محافظ خطا | اگر ابزار شکست خورد (مثلاً اینترنت نبود)، مدل یک پیام اصلاحی می‌گیرد تا جواب معلق `[TOKEN]` نماند |
| محافظ بودجه | به‌محض اینکه مدل فایل/ویرایش تحویل دهد، حلقه تمام می‌شود و کار اعمال می‌شود |

**۲) `/verify` — حلقه‌ی وریفای خودکار** — «اجرا → خطا → اصلاح → اجرا» بدون هیچ دخالت دستی:

```
/verify python main.py        ← یا فقط /verify (دستور آخرِ /run را دوباره وریفای می‌کند)
```

Nova دستور را اجرا می‌کند؛ اگر خطا داد، خطا + فایل‌های درگیر را خودکار به مدل می‌دهد، فایل‌های اصلاح‌شده را **بدون پرسش** اعمال می‌کند (همیشه با بکاپ و `/undo`) و دوباره اجرا می‌کند — تا `NOVA_VERIFY_STEPS` دور (پیش‌فرض ۳). اگر یک فایل تغییر نام داده باشد، دستور `Run:` خودِ مدل برای دور بعد پذیرفته می‌شود. دو محافظ مهم: **دستور سرور** (uvicorn، flask، vite و…) رد می‌شود — برای آن‌ها `/serve` — و **خطای تکراری** (دو دور پشت سر هم با خروجی یکسان) حلقه را متوقف می‌کند تا نسل‌های کند مدل هدر نرود. حلقه‌ی `/auto` هم همین محافظ خطای تکراری را گرفت و پیام اصلاحش حالا پروتکل `=== EDIT: ===` را هم یادآوری می‌کند.

**۳) پروتکل ویرایش جزئی `=== EDIT: ===`** — به‌جای بازنویسی کل فایل برای تغییر دو سه خط:

```
=== EDIT: js/main.js ===
<<<<<<< SEARCH
const limit = 10;
=======
const limit = 25;
>>>>>>> REPLACE
=== END ===
```

قواعد ایمنی این پروتکل (همه در سمت ایجنت چک می‌شوند):

- متن `SEARCH` باید **دقیقاً یک بار** در فایل فعلی پیدا شود؛ صفر بار یا چند بار = رد کامل آن فایل با پیام خطای شفاف (هیچ‌وقت ویرایش نصفه اعمال نمی‌شود)
- فایل باید از قبل موجود باشد (فایل جدید = `=== FILE: ===`)؛ مسیر مثل همیشه سندباکس‌شده؛ فایل‌های خیلی بزرگ رد می‌شوند
- قبل از هر ویرایش بکاپ گرفته می‌شود؛ `/undo` همان کل دسته (فایل + ویرایش) را برمی‌گرداند
- اگر مدل در یک پاسخ هم `=== FILE: ===` و هم `=== EDIT: ===` برای **یک فایل** بدهد، ویرایش رد می‌شود (تناقض؛ نه سکوت و نه خرابی)
- چند بلاک `EDIT` برای یک فایل در یک پاسخ، به‌ترتیب ادغام و اعمال می‌شوند
- نتیجه‌ی عملی: پرامپت خیلی کوتاه‌تر از بازنویسی فایل کامل است → روی پنجره‌ی ۴۰۹۶ توکن به‌مراتب کمتر نصف می‌شود

هر سه قابلیت به **سیستم‌پرامپت مدل** (و `Modelfile` برای اجرای مستقل) هم آموزش داده شده‌اند؛ مدل حالا می‌داند برای تغییر کوچک `EDIT` بدهد، برای فایل جدید `FILE`، و بعد از اصلاح `/verify` را پیشنهاد دهد.

**بعد از آپدیت حتماً مدل را بازسازید:** `ollama create nova-code -f Modelfile` *(دستورالعمل تاریخی v3.x — از نسخه ۵.۱ دیگر مدل سفارشی وجود ندارد؛ این مرحله لازم نیست)*

## 🧩 v2.6 — مدل آگاه از ابزارها (جدید)

از این نسخه، مدل سفارشی `nova-code` **لیست کامل و همیشه به‌روز ابزارها را در پرامپت سیستم خودش می‌بیند**. این لیست در لحظهٔ اجرا از «رجیستری ابزار» داخل `nova.py` تولید می‌شود؛ یعنی:

- اگر ابزاری **اضافه، حذف یا تقویت** شود، فقط یک ورودی در جدول `TOOLS` تغییر می‌کند — راهنمای `/help`، `/status` و مهم‌تر از همه **دانش خودِ مدل** به‌صورت خودکار به‌روز می‌شود. دیگر هیچ پرامپتی نباید دستی همگام شود و هیچ ابزاری از چشم مدل پنهان نمی‌ماند.
- مدل یاد گرفته ابزار درست را **به شما پیشنهاد** دهد: بعد از نوشتن فایل‌ها `/check`، برای سرورهای وب `/serve` (نه `/run`)، و در پایان هر پاسخ کدنویسی، دقیقاً بنویسد چه چیزی را اجرا کنید.
- ابزارهای محرمانه/داخلی (مثل `/status` یا `/export`) به مدل معرفی نمی‌شوند تا پرامپت سبک بماند — فقط ابزارهایی که به کارش ربط دارند (`model: True`).

**توکن جدید `[READ: file]`** — مدل حالا می‌تواند قبل از تغییر یک فایل، **محتوای واقعی آن را ببیند**: کافی است در پایان پاسخ فقط خط `[READ: src/main.py]` را بنویسد؛ ایجنت فایل را (فقط‌خواندنی، داخل سندباکس پوشه پروژه، با سقف حجم) برمی‌گرداند و مدل ادامه می‌دهد. اگر فایل وجود نداشته باشد یا مسیر از پوشه بیرون بزند، پیام خطای کوتاه انگلیسی می‌گیرد و بدون تکرار ادامه می‌دهد. توکن قبلی `[SEARCH: query]` هم سر جایش است.

نکته‌ها:

| نکته | توضیح |
|------|-------|
| یک دور ابزار در هر پاسخ | برای سخت‌افزار ضعیف؛ مدل درخواست ابزار می‌دهد → نتیجه برمی‌گردد → پاسخ نهایی را می‌دهد |
| اولویت با فایل‌ها | اگر مدل در همان پاسخ فایل تحویل داده باشد، فایل‌ها اعمال می‌شوند و توکن ابزار نادیده گرفته می‌شود |
| بدون `nova_search.py` | ابزارهای وب و توکن `[SEARCH:]` خودکار مخفی/غیرفعال می‌شوند؛ بقیه چیزها آفلاین کار می‌کند |
| کار مستقیم با مدل | *(توضیح تاریخی v2.6 درباره‌ی Modelfile — از نسخه ۵.۱ حذف شده؛ حالا هر مدل Ollama را مستقیم هم می‌توانید اجرا کنید و ایجنت همان را با `/model` انتخاب می‌کند)* |

**برای توسعه‌دهنده — افزودن ابزار جدید فقط ۲ قدم:** یک تابع معمولی `def cmd_x(sess, arg)` بنویسید، بعد **یک ورودی** در جدول `TOOLS` اضافه کنید. تمام: `/help`، اجرای دستور، `/status` و (با فلگ `model: True`) آموزش مدل، خودکار انجام می‌شود. حذف یا تغییر ابزار هم به همین سادگی است.

**بعد از آپدیت حتماً مدل را بازسازید:** `ollama create nova-code -f Modelfile` *(دستورالعمل تاریخی v3.x — از نسخه ۵.۱ دیگر مدل سفارشی وجود ندارد؛ این مرحله لازم نیست)*

## ❓ سوالات متداول

**کدام مدل را انتخاب کنم؟**
هر مدلی که با Ollama نصب کنید، Nova هنگام شروع پیدا می‌کند. نصب‌کننده روی سیستم‌های ضعیف (≤ ۵ گیگ رم) پایه سبک `qwen2.5-coder:1.5b` را پیشنهاد می‌دهد و روی سیستم‌های قوی‌تر `qwen2.5-coder:3b` را — و اگر از قبل مدلی نصب باشد، هیچ دانلودی انجام نمی‌دهد. انتخاب خودکار Nova اولویت را به مدل‌های کدنویس می‌دهد و در حالت برابر، مدل سبک‌تر را برمی‌گزیند. مدل دیگر: `ollama pull <model>` و بعد `/model <name>` (یا شماره ردیف) داخل ایجنت.

**پاسخ‌ها واقعاً می‌توانند چند دقیقه طول بکشند؟**
بله — روی CPU ضعیف بارگذاری مدل + پردازش پرامپت قبل از اولین توکن، دقیقه‌ها زمان می‌برد. Nova هیچ‌وقت پاسخ را وسط کار قطع نمی‌کند (مهلت‌ها فقط سقف سکوت‌اند)، تایمر `[waiting]` زنده بودن را نشان می‌دهد، مدل ۶۰ دقیقه در رم می‌ماند تا مکث‌ها گران نباشند، و اگر خودتان قطع کنید می‌توانید با `continue` ادامه دهید. جزئیات: بخش «لپ‌تاپ ضعیف».

**واقعاً می‌شود یک وب‌سایت کامل باهاش ساخت؟**
برای سایت‌های استاتیک و تعاملی (لندینگ، پورتفولیو، دشبورد ساده، بازی HTML) بله — دقیقاً همان کاربرد هدف است. پروژه را مرحله‌به‌مرحله جلو ببرید: بسازید → `/serve` ببینید → مشکلات را با جزئیات گزارش کنید → مدل اصلاح می‌کند. برای بک‌اند و دیتابیس، اسکریپت‌های پایتون ساده خوب جواب می‌دهد؛ پروژه‌های خیلی بزرگ را به بخش‌های کوچک تقسیم کنید.

**ایجنت چطور خودش خطاها را می‌فهمد؟**
سه لایه: (۱) `/run` خروجی و خطای واقعی برنامه را برمی‌گرداند، (۲) مسیر فایل‌های نام‌برده در traceback خودکار پیوست می‌شود تا مدل کد واقعی را ببیند، (۳) `/check` سینتکس همه فایل‌ها را قبل از اجرا می‌سنجد. ترکیب این سه، دیباگ را برای مدل کوچک ممکن می‌کند.

**مدل‌هایم را چطور به‌روز نگه دارم؟**
پس از انتشار نسخه جدید یک مدل (مثلاً Qwen3-Coder): `ollama pull qwen3-coder:3b` — تمام. دفعه‌ی بعد که Nova اجرا شود مدل جدید را در جدول `/model` می‌بینید؛ با `/model qwen3-coder:3b` به آن سوییچ کنید (در پروفایل پروژه هم ذخیره می‌شود).

**حذف کامل:**
```bash
ollama rm qwen2.5-coder:3b   # و هر مدل دیگری که با ollama list می‌بینید
```
